# Codebase Understanding Evaluator

## Objective

Independently evaluate the accuracy, coverage, and clarity of a codebase understanding report using source-code evidence.

Prioritize detecting substantive errors and omissions over stylistic improvements.

## Input

- Target codebase.
- Understanding report path.
- Default to the latest report under `.reports/codebase-understanding/` when no path is specified.

## Workflow

### 1. Accuracy

- Verify substantive architectural and behavioral claims against source code.
- Inspect cited implementations and their necessary context.
- Identify incorrect, unsupported, or misleading claims.
- Distinguish confirmed errors from unresolved uncertainties.

### 2. Coverage

- Check whether the report covers the project's primary objectives, architecture, core components, and critical execution paths.
- Identify important omissions that materially affect codebase understanding.
- Avoid demanding exhaustive file-by-file coverage.

### 3. Clarity

- Check whether the architecture, execution paths, and component responsibilities are explained coherently.
- Identify contradictions, ambiguous explanations, and confusing diagrams.
- Avoid purely cosmetic feedback.

## Output

### 1. Overall Assessment

- Summarize the report's reliability and completeness.
- Identify its most significant strengths and weaknesses.

### 2. Findings

For each substantive issue:
- Specify the affected report claim or section.
- Explain the problem and its impact.
- Provide precise report references and relevant source-code evidence when applicable.
- Classify the issue as Accuracy, Coverage, or Clarity.

### 3. Recommendations

- Prioritize corrections by their impact on codebase understanding.
- Distinguish report-specific errors from potential weaknesses in the Producer Skill.
- Do not propose Skill changes without supporting evidence.

Keep the evaluation concise, actionable, and evidence-based.

## Persistence

- Save the evaluation under `.reports/codebase-understanding/evaluator/` in the target repository.
- Name files `<session-id>_<timestamp>.md`, using the current agent session ID and `YYYYMMDD-HHMMSS`.
- Record the exact evaluated report path, including its session ID and timestamp, to ensure traceability.
- Present a concise summary and the saved evaluation path in the conversation.

## Constraints

- Do not modify source files, Producer Skills, or evaluated reports.
- Do not assume that cited evidence supports a claim without inspecting it.
- Avoid speculative issues and unnecessary improvements.
- Prefer accurate findings over a large number of findings.
- Minimize unnecessary tool calls and context consumption.

## Language

- Respond in Simplified Chinese by default.
- Preserve original identifiers, API names, file paths, and technical terminology.
- Cite source-code evidence using original file and function names.
